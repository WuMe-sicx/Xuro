## Mandatory Development Workflow

**Before touching code** for any task that touches multiple files _or_ has observable runtime / build / external behavior changes (single-file typo/format/comment fixes are exempt):

1. Read [`docs/dev_workflow.md`](docs/dev_workflow.md).
2. Create the task's TODO doc under [`docs/todos/active/`](docs/todos/active/) using [`docs/todos/_template.md`](docs/todos/_template.md). Fix goal, scope, acceptance criteria, and step-by-step plan **before** any code change.
3. During development, tick steps in the TODO doc as they land and reference produced files / commit hashes.
4. **On feature completion**: append the `✅ 完成标记` block (with `/init` line + timestamp), then **actually run `/init`** to refresh this `CLAUDE.md`. Move the TODO file from `active/` to `done/`.
5. Cancelled tasks go to `docs/todos/cancelled/` with a `⛔ 取消标记` block — they do **not** run `/init`.

## Project Overview

Xuro is a Flutter-based ASMR.ONE client app (package name: `xuro`, app ID: `com.xuro`). It provides ASMR audio streaming with background playback, subtitle/lyric display, playlists, and caching. Licensed CC BY-NC-SA.

## Build & Development Commands

This project pins Flutter **3.27.0** via [`.fvmrc`](.fvmrc). Prefer `fvm flutter ...` to ensure the pinned SDK is used; substitute plain `flutter` only if you have it on PATH and matching the pinned version.

```bash
# Install dependencies
fvm flutter pub get

# Run code generation (freezed + json_serializable)
fvm dart run build_runner build --delete-conflicting-outputs

# Run the app (debug)
fvm flutter run

# Run all tests
fvm flutter test

# Run a single test file
fvm flutter test test/data/services/api_service_url_test.dart

# Static analysis (use this before commit). `withOpacity` has been fully
# migrated to `.withValues(alpha:)` (0 call-sites) — do not reintroduce it.
# A few pre-existing, UI-unrelated warnings remain (unused import/element in
# playback_controller / playback_context / recommendation_cache_manager /
# playlists_content, and a logger `printTime` deprecation) — don't add new ones.
fvm flutter analyze

# Analyze a single subtree (faster feedback while iterating)
fvm flutter analyze lib/widgets/sidebar/

# Build release APK
fvm flutter build apk --release

# Build iOS (no codesign)
fvm flutter build ios --no-codesign
```

**Environment:** Dart SDK >=3.2.3 <4.0.0, Flutter 3.27.0 (FVM-pinned), Android min SDK 21 / target 33, Java 17.

**Renderer (Android):** Impeller is **disabled** via `io.flutter.embedding.android.EnableImpeller=false` in `android/app/src/main/AndroidManifest.xml` — Android builds use the Skia backend. Reason: real-device `Vulkan: ErrorDeviceLost` → `SIGSEGV in libvulkan.so::CmdEndRenderPass+4` long-session crashes on Xiaomi HyperOS 3 / Android 16 + Adreno (driver-level GPU fault, zero Dart frames). Don't re-enable Impeller without first upgrading the Flutter SDK (3.29+ has many Adreno fixes) and re-running a 30+ min real-device session — see `docs/todos/active/20260515-upgrade-flutter-sdk.md`. iOS continues to use Impeller (default and stable there).

## Architecture

Clean Architecture with three layers, using **Provider (ChangeNotifier)** for state management and **GetIt** for dependency injection.

### Layer Structure

- **`lib/core/`** - Platform services and infrastructure
  - `di/service_locator.dart` - GetIt DI container setup (entry point for all service registration)
  - `audio/` - Audio playback system: `IAudioPlayerService` interface + implementation, PlaybackEventHub (event bus pattern), state persistence, notification handling. **Lock-screen media notification invariants** (`notification/audio_notification_service.dart` + `audio_player_handler.dart`): the Android MediaStyle notification only renders a duration-backed seekbar when the `MediaItem` carries a non-null `duration`, but at `trackChange` time the source is usually not loaded yet — so `AudioNotificationService` listens to `playbackState` and re-pushes the `MediaItem` once the real duration is known. It also injects `ISubtitleService` and, since MediaStyle has no dedicated lyric line, **puts the current subtitle line in the `artist` row** (falls back to the real artist when no line is active); `MediaItem` is only re-pushed when track/duration/lyric actually changes (lyric is `distinct`-guarded) so artwork isn't refetched. The state stream only fires on play/pause/buffer transitions, so `AudioPlayerHandler` additionally re-emits `playbackState.copyWith(updatePosition:…)` from a **1s-throttled** `playbackProgress` subscription — `copyWith` auto-stamps `updateTime = now`, letting the lock-screen seekbar extrapolate between emissions. There is no native lock-screen *scrolling* lyric (vendor-only API, deliberately out of scope). **Playback-state persistence invariants** (`state/playback_state_manager.dart` + `storage/playback_state_repository.dart`, key `last_playback_state` in SharedPreferences): the persisted `PlaybackState` is **deliberately slim** — only `work / files / currentFile / playMode / position / timestamp`. `playlist` / `currentIndex` are **not persisted**: on restore, `restorePlaybackState()` rebuilds the context via the `PlaybackContext({work, files, currentFile, playMode})` factory which re-derives playlist/index from `files`+`currentFile` (`playback_context.dart:51-68`), so persisting them was dead, duplicated tree data. Old JSON carrying those keys still loads (json_serializable ignores unknown keys — no migration). Saves are **throttled to 20s** (debounce reset on every `playerStateStream` event); explicit flushes happen on `pause()`, playback completion, and best-effort in `dispose()`. `stop()` clears the persisted key so a stopped session isn't restored. **All persistence is serialized through a single `_persistChain` future + a `_persistSuppressed` tombstone**: `clearSavedState()` sets the flag synchronously and appends the `remove` to the chain tail, so a stop's `remove` can never be overtaken by an in-flight fire-and-forget `saveState()` (which would otherwise write a stopped session back); `saveState()` snapshots `context`/`positionMs` at call time and re-checks suppression inside the chain; `updateContext(non-null)` lifts suppression for new playback. Don't reintroduce direct `_stateRepository` writes that bypass the chain
  - `subtitle/` - Subtitle/lyric system: `ISubtitleService` interface, parsers (VTT etc.), subtitle loader with caching. **`SubtitleImportService` file/DB atomicity invariants** (`subtitle_import_service.dart`, paired with `UserSubtitleRepository` SQLite + files under app-docs `user_subtitles/<workId>/`): import must never leave the user's existing subtitle in a worse state on failure. The write sequence is: `picked.copy(tmpPath)` → if a file already sits at `destPath`, move it aside to `bakPath` (`backedUp=true`) → `tmp.rename(destPath)` (atomic on same FS) → `repository.upsert`. On success: delete the backup, then best-effort delete a *different-path* old file (ext change). On any failure: delete tmp, and if `backedUp` restore `bak→destPath`, then rethrow → `ImportResult.ioError`. Never delete the old file/DB row before the new import is fully confirmed (the old "delete-old → copy → upsert" order could destroy the user's subtitle, and `File.copy` is non-atomic). `removeImportedSubtitle` removes the **DB row first** behind a `dbRemoved` flag and only deletes the local file if the DB removal succeeded — a stale row pointing at a missing file makes the app think a subtitle still exists, whereas an orphan file is harmless. These ordering rules (consistency-critical DB op gated correctly relative to the file op; existing data preserved until success) must hold for any future change here
  - `platform/` - Platform-specific: `ILyricOverlayController` (Android floating lyric window, dummy on other platforms), `WakeLockController`, `SleepTimerController`, `BackgroundPlayController`. **Sleep-timer / background-play invariants**: `SleepTimerController` is a **session-only** `ChangeNotifier` (NOT persisted — re-arming on launch is bad UX and would tangle the `playback_state` invariants); on expiry it calls `IAudioPlayerService.pause()` (deliberately `pause()`, never `stop()` — `stop()` clears the persisted key); `setMinutes`/`cancel`/`dispose` always cancel the prior `Timer` first (no double-timer / no post-dispose callback). `BackgroundPlayController` is a `WidgetsBindingObserver` with an idempotent `initialize()` (mirrors `CacheLifecycleManager`, registered lazy + `initialize()`d in `main()` after `CacheLifecycleManager`) that pauses on `AppLifecycleState.paused` **only when** `AppSettingsService.backgroundPlayEnabled == false`; default `true` preserves the always-on background behavior, it never auto-resumes and never touches `audio_service`/handler internals. Both are consumed in Settings → 播放; `SleepTimerController` also drives the player AppBar quick-timer action (opens the shared `SleepTimerDialog`, icon tinted `primary` while active). **Floating lyric invariants** (Android `LyricOverlayService.kt` + `lyric_overlay.xml`): the overlay is **pass-through by default** — `FLAG_NOT_TOUCHABLE` **and** `LayoutParams.alpha = 0.8` (`PASS_THROUGH_ALPHA`). The alpha is load-bearing, not cosmetic: Android 12+ `getMaximumObscuringOpacityForTouch()` (default 0.8) means an opaque `TYPE_APPLICATION_OVERLAY` still eats the underlying app's touches even with `FLAG_NOT_TOUCHABLE` — don't raise it above 0.8 in pass-through mode. "Edit mode" (`setEditable(true)`, entered via **long-press** the lyrics icon in `PlayerScreen`) drops `FLAG_NOT_TOUCHABLE` and restores `alpha = 1.0` so the user can drag; drag is **Y-axis only** (X is fixed `CENTER_HORIZONTAL`, only `KEY_Y` persisted — old `KEY_X` is intentionally ignored). `hide()` force-resets edit mode on both Kotlin and `LyricOverlayManager` sides. **Two ways to enter drag mode, different persistence**: long-pressing the lyrics icon in `PlayerScreen` is a *transient* session toggle (`toggleEditable`, reset by `hide()`); the **Settings → 悬浮歌词** switch is the *persisted* default — it writes `AppSettingsService.lyricOverlayUnlocked` via `LyricOverlayManager.setUnlockedPreference` and `show()` always re-applies that persisted preference last, so it is the source of truth on each show. `LyricOverlayManager` therefore depends on `AppSettingsService` (DI order: `AppSettingsService` is registered before `setupSubtitleServices()`). The lyric is a `FrameLayout` with two stacked `TextView`s (black `Paint.Style.STROKE` behind, white fill in front) — there is **no background box**; keep both TextViews' size/padding/font identical or the stroke desyncs. `setEditable` must stay wired through interface → impl → dummy → manager → native `LyricOverlayPlugin`.
  - `theme/` - Theme is determined by **two axes**: `ThemeMode` (light/dark/system, owned by `ThemeController`) × `ColorVariant` (blue/mono/green, owned by `AppSettingsService`). `AppColors.lightSchemeFor(variant)` / `darkSchemeFor(variant)` produce 6 hand-rolled `ColorScheme`s; surfaces are neutral, only `primary` / `onPrimary` / `primaryContainer` rotate. Do not use `ColorScheme.fromSeed` here — it would derive secondary/tertiary in another hue and break the "two-color" simplification. **Design-token classes** (mandatory; no magic numbers in UI): `AppSpacing` (`space4..space64` 4px grid + `pageMobile/pageTabletDesktop`), `AppRadius` (`sm8/md12/lg16/full999` + const `*All` `BorderRadius`; `app_theme` card radius = `AppRadius.mdAll`), `AppTextStyles` (规范 §1.2 七档；**deliberately carries no color** so the three-variant invariant holds), `AppAnimations`/`MicroInteractions` (durations/curves — never hardcode `Duration`/`Curve`). **Three-variant invariant**: any reusable widget MUST take colors from `Theme.of(context).colorScheme.*` (or these tokens), never hardcode a color — switching `ColorVariant` must change *only* accent pixels. New atoms get a "three-variant" widget test (`test/widgets/common/atom_three_variant_test.dart` pattern). `docs/ui-design-spec.md` is **v4.0**, rewritten to this real two-axis system + the atom-reuse matrix (the reference-image mockup is the visual basis; the old "purple `fromSeed`" spec is gone).
  - `cache/` - RecommendationCacheManager; `CacheCoordinator` (unified clean/clear API); `CacheLifecycleManager` (a `WidgetsBindingObserver` singleton — startup cleanup is deferred to `addPostFrameCallback` so the stat-heavy scan doesn't fight first-frame render; `resumed` triggers immediate cleanup; both gated by a 6h throttle + reentrancy flag). **`AudioCacheManager.cleanCache()` LRU invariants**: it must collect `(file, stat)` once via `await file.stat()` and NEVER call `statSync()` in a sort comparator (O(N log N) blocking FS calls froze frames). Eviction is true LRU: delete expired (>30d) first, then sort survivors by `stat.modified` ascending and delete oldest-first until `totalSize <= _maxCacheSize` (1GB), decrementing `totalSize` per delete. A delete failure (file in use) only skips that file — it does NOT abort the sweep. **An expired file whose delete fails must be added back into the `live` set**, not dropped: otherwise it still occupies disk but escapes capacity accounting, and actual usage can blow far past the limit. `modified` is the LRU proxy (atime is unreliable cross-platform; `LockCachingAudioSource` writes as it downloads so modified ≈ last-cached). There is intentionally no per-track pre-download capacity guard (a full dir scan on every play start would hurt the very fluency this protects)
  - `download/` - `DownloadService` + `DownloadRepository` (`downloads` SQLite table, `UNIQUE(work_id, file_key)`): local download of any work `Child` (audio / video / **subtitle**) for offline playback. Uses an **independent `Dio()`** (no `AuthInterceptor`, doesn't rotate with node — `mediaDownloadUrl` is an API-issued presigned absolute URL). **落盘 location invariants**: only `_baseDir()`/`_workDir()` resolve the directory — **Android** uses `getExternalStorageDirectory()` (`/storage/emulated/0/Android/data/<pkg>/files/downloads/<workId>/`): permission-free on every Android version, PC-visible via USB/MTP, uninstall-cleaned; null/throw → fallback to internal `getApplicationDocumentsDirectory()`. **Non-Android always internal** (`getExternalStorageDirectory()` throws `UnsupportedError` on iOS — the `Platform.isAndroid` guard is load-bearing, don't remove it). **No migration of pre-existing internal-dir downloads** is needed or wanted: `DownloadRepository`/`DownloadEntry`, `findCompleted`/`localPathIfDownloaded`, and offline playback (`playlist_builder.dart` builds `Uri.file()`) all key off the DB's **absolute `file_path`**, so old internal files keep getting hit & played while new ones land external — don't add a migrator or switch the DB to relative paths. **Stable identity** `fileKey = md5(hash | mediaDownloadUrl | title)` (NOT the display name — same-named files under different dirs/URLs must be distinct downloads). **Disk layout** = `downloads/<workId>/<fileKey>/<sanitized original title>`: the on-disk filename is deliberately the **API's original `Child.title`** (so PC users see the real names, not an md5), and physical uniqueness is provided by the per-`fileKey` subdir — two distinct files in one work that share a `title` (e.g. each chapter's `01.mp3`) never collide. Don't flatten this back to `downloads/<workId>/<name>` (re-introduces the same-name overwrite that destroys a good file) or rename files back to the md5. `diskFileName = sanitizeFileName(title)`; `sanitizeFileName` is **Unicode-preserving** (keeps JP/CN letters — do NOT revert to the old ASCII-only `[^a-zA-Z0-9._\- ]` scrub, it mangled every Japanese ASMR title), replaces only true FS-illegal chars `[\x00-\x1F/\\:*?"<>|]`, strips leading+trailing dots/space (leading dot = hidden file on macOS/Linux; trailing = FAT eats it), `_`-prefixes Windows reserved stems (`CON`/`NUL`/`COM1`…), falls back to `file`, and UTF-8-byte-clamps to `_maxNameBytes` (180, FAT/exFAT 255-byte limit minus headroom for `.dl_tmp`/`.dl_bak`) without splitting a multibyte char — these are unit-tested boundaries, keep them. **Atomic write** mirrors `SubtitleImportService`: download to `.dl_tmp` → move any existing dest to `.dl_bak` → `rename` → DB `upsert`; any failure deletes tmp, restores bak, and never destroys an existing good file before the new one is confirmed (tmp/dest/bak are all in the same `<fileKey>` subdir so `rename` is same-volume atomic). **The entire `download()` body — including the pre-flight `findCompleted` dedup, `_destPath` resolution and tmp/bak construction — runs inside one `try`; `destPath`/`tmpFile`/`bakFile` are nullable-declared before it and the catch null-guards cleanup, so a DB open/migration, `path_provider`/dir-create or `File.exists` permission failure returns `DownloadStatus.ioError` (never an uncaught async throw). Both download dialogs (`media_download_dialog`/`batch_download_dialog`) also wrap their `await widget.download(...)` and pop a failed result on any throw, so the `PopScope canPop:false` progress sheet can't get stuck. Don't move the dedup / path resolution back outside the `try`.** `_pruneEmptyDir` best-effort removes the now-empty `<fileKey>` dir after a file delete (keeps the user-visible folder tidy; failure harmless). **Capacity** is true LRU mirroring `AudioCacheManager`: `enforceCapacity` scans the whole DB via `listAllOldestFirst()` by absolute path (NOT a dir scan), prunes rows whose file vanished, keeps & still counts (DB `size`) files that can't be `stat`/deleted, and excepts the just-finished download from eviction so a fresh download can't be reclaimed before it's returned. `removeDownload` deletes the DB row first (consistency-critical: a stale row makes the app think a file is downloaded) then best-effort deletes the file (an orphan file is harmless disk waste). Don't bypass these orderings. **File-type classification — extension wins over the API `type`** (`DetailViewModel._hasVideoExtension`/`_isAudioChild`, mirrored in `WorkFileItem` and the `detail_screen` `onFileTap` order which checks `isVideoFile` **before** `isAudioFile`): asmr.one mislabels some videos (e.g. "介绍视频.mp4") as `type:"audio"`. If trusted, such a file gets routed into the audio play pipeline, the playlist is filtered to nothing by extension, and `PlaybackContext.validate` throws "播放列表为空" → user just sees "播放失败" and can neither play nor download it. So a known video extension (`{mp4,mkv,mov,avi,webm,m4v}` — deliberately excludes `m4a`/other audio exts) is treated as **video** regardless of `type`; `isAudioFile = type==audio && !videoExt`; videos route to the download-then-open-externally flow. `playFile`'s guard uses `isAudioFile` (not a raw `type` check) as defense-in-depth. Don't add a new code path that branches on `type=='audio'` alone for play/batch — go through `isAudioFile`/`_isAudioChild`. **Batch + audio/subtitle pairing** (orchestrated in `DetailViewModel`, not the service): `collectAudioWithSubtitles(children)` is a **pure static** recursive walk that flattens the work tree to `(audio, matchedSubtitle?)` pairs — the subtitle is matched **within the same `children` sibling list** via `SubtitleMatcher` (same immediate-dir semantics as `SubtitleLoader.findSubtitleFile`/`FilePath.getSiblings`), unit-tested. `downloadFolder(folder)` (folder `null` = whole work) downloads those pairs **sequentially** (parallel would fight the LRU/atomic invariants) with aggregate `BatchDownloadOutcome`; single-file `downloadFile` also best-effort downloads the matched subtitle (subtitle network/IO failure only logs, never changes the audio's `DownloadResult`; but a subtitle download **cancel** must propagate to the batch — checked after the subtitle step AND at loop tail so a cancel during the last item's subtitle isn't misreported as "完成"). Idempotent dedup is still `DownloadService.download`'s job (don't re-add a guard in the VM). `BatchDownloadDialog.dispose()` cancels its `CancelToken` (token drives the `downloadFolder` loop's top/tail checks + dio abort) so a programmatically-dismissed dialog/page doesn't keep writing. *Note:* user-**imported** subtitles (`SubtitleImportService` → app-docs `user_subtitles/`) are a separate flow and stay internal — only *downloaded* `Child` subtitles follow the external-dir rule above. **Offline subtitle priority** (`PlayerViewModel._loadSubtitleIfAvailable`): user-imported → **downloaded-local** (the auto-matched subtitle `Child` resolved via `DownloadService.localPathIfDownloaded` + `SubtitleImportService.loadLocalSubtitle`, so a downloaded subtitle works with no network) → online `mediaDownloadUrl`; the `subtitleFile == null` early-return still clears the subtitle, and every new `await` keeps the `_loadVersion != version` race guard. **Subtitle preview** (`SubtitlePreviewScreen`, opened by tapping a `.vtt/.lrc/.srt/.txt` leaf in the file tree — `WorkFileItem` makes those tappable, routed in `detail_screen.dart`): read-only; resolves content local-first then URL via `SubtitleLoader.loadRawContent`, `parseOrNull` renders a timeline list, and **any parse failure (incl. thrown) falls back to raw text** — `parseOrNull` must keep swallowing parse exceptions so the screen never shows "加载失败" for an unparseable-but-fetched file
  - `database/` - `database_service.dart` (SQLite local persistence; single `user_subtitles` table, schema version 1). **Concurrency + migration invariants**: it caches a `Future<Database>?` (`_databaseFuture`), NOT a resolved `Database` — `database => _databaseFuture ??= _open()` has no `await` between the null-check and the assignment, so under Dart's single-isolate loop concurrent first-access (the four `UserSubtitleRepository` methods each independently `await _db.database`) share one in-flight open instead of double-`openDatabase()`-ing. `_open()` clears `_databaseFuture` on failure so one failed open doesn't permanently poison the getter. Don't revert this to `Database? _database ??= await ...` (that reintroduces the double-open race). `_onUpgrade` walks an ordered `_migrations` map `{version: (db) async {...}}` for `v in (oldVersion, newVersion]` (multi-version-jump safe); to change schema: bump `_databaseVersion` AND add the step to `_migrations` (never edit `_onCreate` for an existing-install migration)
  - `image/cache/` - Image cache layer used by network image widgets
  - `settings/` - `app_settings_service.dart` (user preferences persistence: serverUrl, smartPath, audioFormatOrder, colorVariant, `lyricOverlayUnlocked`, `backgroundPlayEnabled` (persisted, **default `true`** = always-on background play preserved; `false` opt-out is enforced by `BackgroundPlayController`), `hasSubtitleFilter`). **`hasSubtitleFilter` is the single source of truth for the shared "字幕作品" list filter**: `HomeViewModel`/`PopularViewModel`/`RecommendViewModel`/`SimilarWorksViewModel` all read it via `getIt<AppSettingsService>().hasSubtitleFilter` and write via `setHasSubtitleFilter(...)` — they must NOT cache it locally or re-persist it in `dispose()` (the old per-VM `SharedPreferences.getInstance()` + dispose write-back let a later-disposed VM clobber a fresh value with a stale one). VMs deliberately do *not* listen to `AppSettingsService` for this (no cross-screen live sync); each screen reads it at its own init and applies on its own `refresh()`. `HomeViewModel`'s `home_filter_state` (sort `FilterState` JSON) stays VM-private prefs — it's single-writer with no cross-VM race, and `FilterState` is a presentation model that must not be pulled into the core layer

- **`lib/data/`** - Data layer
  - `models/` - Freezed immutable data classes (auto-generated `.freezed.dart` + `.g.dart` files)
  - `services/api_service.dart` - Dio HTTP client; baseUrl is read from `AppSettingsService.serverUrl` and updated when the user switches nodes
  - `services/auth_service.dart` - Login (`/auth/me`) and register (`/auth/reg`); also injects `AppSettingsService` so auth requests follow the user's selected node. Defines `RegisteredButNotLoggedInException` for the case where account creation succeeds but the auto-login fallback fails — callers must distinguish this from a register failure
  - `services/interceptors/auth_interceptor.dart` - Dio auth interceptor. Calls `AuthRepository.getAuthData()` on **every request** — this is cheap only because `AuthRepository` caches in memory (see below); don't make the interceptor decode storage per request
  - `services/exceptions/network_exception.dart` - `NetworkException.fromDioException` maps Dio errors to a `NetworkErrorType`. `userMessage` is the **single source** of user-facing copy: `connectionError`/`timeout` → `Strings.networkVpnHint` ("请先连接 VPN 服务", because asmr.one is geo-blocked so any connection failure ≈ VPN off), `authError` (401/403) → `Strings.loginRequired`, else the technical `message`. `isAuthError` lets callers branch on auth failures. ViewModels should consume `userMessage`/`isAuthError`, not `e.toString()`
  - `services/update_service.dart` + `services/exceptions/update_exception.dart` - In-app update check. `UpdateService` has its **own** Dio fixed to `https://api.github.com` (GitHub headers `Accept: application/vnd.github+json` + `X-GitHub-Api-Version`); it deliberately does **not** subscribe to `AppSettingsService` and carries no `AuthInterceptor` (GitHub host is unrelated to asmr node switching). CI publishes every release with `prerelease: true`, so `/releases/latest` (skips prereleases) is unusable — `checkForUpdate` GETs `/releases?per_page=10`, keeps only tags matching `^v?\d+\.\d+\.\d+$`, and picks the **semver max** (not list `[0]`) via static `UpdateService.compareSemver`. Errors map to `UpdateException`/`UpdateErrorType` — **never reuse `NetworkException` here**: its copy is asmr-specific (403→"请先登录", connection fail→VPN hint), wrong for GitHub where 403/429 = rate limit. `UpdateInfo` is **Freezed-only (no `.g.dart`)** with a custom `fromReleaseJson` factory (fields are derived, not 1:1 JSON) that throws `FormatException` (service translates to `invalidPayload`) — the model has no service-layer imports. `compareSemver`/`selectLatestRelease`/`fromReleaseJson`/`fromDioException` are `static`/pure and network-free unit-tested
  - `repositories/` - Repository implementations (AuthRepository, audio state). **`AuthRepository` security + concurrency invariants**: the `AuthResp` blob (contains the bearer token) is stored in `flutter_secure_storage` (Android EncryptedSharedPreferences / iOS Keychain), **not** plaintext SharedPreferences. It keeps an in-memory cache (`_cached`/`_loaded`) so `AuthInterceptor` does zero storage/JSON work per request after the first load; `getAuthData()` dedupes concurrent first-loads via `_loadFuture ??= _loadAndMigrate()` (no `await` between null-check and assign). One-time migration of legacy plaintext `auth_data`: only `prefs.remove` **after** a successful secure write — migrate-fail keeps plaintext and does NOT log the user out. **Defensive degrade**: any secure-storage read/write failure (Keystore broken on some OEM ROMs) falls back to prefs rather than crashing or logging out — worst case it degrades to the old plaintext behavior. All secure/prefs *mutations* (legacy migrate, save, clear) run through a single `_serialize`/`_writeLock` chain so issue-order == persist-order — without this, an in-flight legacy-migrate `_secure.write(oldToken)` could complete after a concurrent `saveAuthData(newToken)` and resurrect the old token in secure storage. The `if (_loaded) return _cached;` guards before each cache commit protect the authoritative in-memory state when a save/clear lands during a load. Don't bypass the chain or the guards when changing this file

- **`lib/presentation/`** - Presentation layer
  - `viewmodels/` - ChangeNotifier ViewModels (one per screen). `PaginatedWorksViewModel` is the base class for all paginated list screens
  - `viewmodels/player_viewmodel.dart` - Central player state, depends on AudioService + SubtitleService + EventHub
  - `layouts/` - `work_layout_config.dart` / `work_layout_strategy.dart` (responsive grid sizing — see ui-design-spec §5). `groupWorksIntoRows` has a **class-level single-slot memo** keyed by `identical(works)` + columnCount (returns the same `List` instance on hit; recomputes on page/column change) — `WorkLayoutStrategy` is `const` so the cache is static, not instance state
  - `models/filter_state.dart` - UI-only state object for the filter panel
  - `widgets/auth/` - Auth UI widgets: `LoginDialog` and `RegisterDialog`. They cross-link via root navigator (`useRootNavigator: true`) so the sidebar's local dark `Theme` doesn't leak into the dialog, and call `AuthViewModel.clearError()` on the way out to avoid stale error text in the freshly opened dialog

### API

Two Dio clients, both pointed at the user-selected node:
- `ApiService` — content endpoints (`/works`, `/tracks/{id}`, `/search/{keyword}`, `/review`, `/recommender/*`, `/playlist/*`, `/tags/`, `/circles/`, `/vas/`, `/workInfo/{id}`). Auth header added by `AuthInterceptor`. **`searchWorks` must build its URL via `ApiService.buildSearchUri` (`Uri.replace(pathSegments:[...])` + `_dio.getUri`), not string-concatenated `'/search/$keyword'`**: some tag names contain `/` (e.g. `巨乳/爆乳`); a concatenated `%2F` gets decoded back to `/` inside Dio's `Uri.parse`, the server splits the path → 404. `buildSearchUri` is `static` + unit-tested precisely so the keyword stays one path segment. Apply the same pattern to any future endpoint that puts user/tag text in the **path** (query params are unaffected).
- `AuthService` — `/auth/me` (login) and `/auth/reg` (register). Owns its own Dio instance, no auth interceptor.

Both services subscribe to `AppSettingsService` and rotate `dio.options.baseUrl` when the user switches nodes. Available nodes (defined in `AppSettingsService.serverOptions`):
- `https://api.asmr.one/api` (主站, default)
- `https://api.asmr-100.com/api` / `-200` / `-300` (mirror nodes)

When adding a new HTTP-touching service, follow the `_onSettingsChanged` pattern in `ApiService`/`AuthService` — don't hardcode the host. **Deliberate exception:** `UpdateService` is a third Dio client hardwired to `https://api.github.com` and intentionally does *not* follow this pattern — GitHub is unrelated to asmr node switching. Only the asmr-content/auth services rotate with the selected node.

### Error-prompt UX (connection vs. login state)

A list-page error must communicate the **right recovery action**, not just "出错了 + 重试". This invariant spans four layers — keep them consistent when adding a new paginated screen:

1. **Data**: `NetworkException.userMessage` centralizes the copy (VPN hint for connection/timeout, "请先登录" for 401/403). Don't surface `e.toString()` to users.
2. **ViewModel**: list ViewModels (`FavoritesViewModel`, `RecommendViewModel`) expose `bool isLoginError` alongside `String? error`. Set it `true` in the not-logged-in early return **and** when a caught `NetworkException.isAuthError` is true; reset to `false` before each load and on non-auth errors. The `catch` block routes through `NetworkException.userMessage`.
3. **Widget**: `EnhancedWorkGridView` and the legacy `WorkGridView` take `isLoginError` + `onLogin` (both optional, defaulting to retry behavior so other screens are unaffected). When `isLoginError && onLogin != null` they render a **"去登录" button instead of "重试"** (retrying a not-logged-in request is pointless). `GridError` owns the actual branching.
4. **Screen**: content screens pass `isLoginError: vm.isLoginError` and an `onLogin` that opens `LoginDialog` on the **root navigator** (`useRootNavigator: true`), `await`s it, and reloads the list if `context.read<AuthViewModel>().isLoggedIn` afterward. The standalone `FavoritesScreen` (sidebar route, still on legacy `WorkGridView`) is wired the same way for parity. `RecommendContent`'s `Selector` record must include `isLoginError` so the grid rebuilds when it flips.
