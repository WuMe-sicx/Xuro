## Mandatory Development Workflow

**Before touching code** for any task that touches multiple files _or_ has observable runtime / build / external behavior changes (single-file typo/format/comment fixes are exempt):

1. Read [`docs/dev_workflow.md`](docs/dev_workflow.md).
2. Create the task's TODO doc under [`docs/todos/active/`](docs/todos/active/) using [`docs/todos/_template.md`](docs/todos/_template.md). Fix goal, scope, acceptance criteria, and step-by-step plan **before** any code change.
3. During development, tick steps in the TODO doc as they land and reference produced files / commit hashes.
4. **On feature completion**: append the `✅ 完成标记` block (with `/init` line + timestamp), then **actually run `/init`** to refresh this `CLAUDE.md`. Move the TODO file from `active/` to `done/`.
5. Cancelled tasks go to `docs/todos/cancelled/` with a `⛔ 取消标记` block — they do **not** run `/init`.

Companion specs: [`docs/guidelines_zh.md`](docs/guidelines_zh.md) (architecture / code style), [`docs/ui-design-spec.md`](docs/ui-design-spec.md) (visual / animation — **v5.0, rewritten against the Modernist system**; it also carries a §8 "known gaps" table so the same missing pieces aren't rediscovered), [`docs/audio_architecture.md`](docs/audio_architecture.md) (audio subsystem). On conflict: `dev_workflow > subsystem doc > general guidelines`.

**Visual source of truth** is the Claude Design project *Flutter ASMR播放器设计* (`f11e0a02-12c2-476f-8591-aaf9384c4922`, file `ASMR Player.dc.html`) and its `_ds/modernist-*/styles.css`. The standing rule from several rounds of this: **a screen the mockup didn't draw is not a screen to delete, and a feature the mockup drew is not a feature to invent.**

## Project Overview

Xuro is a Flutter-based ASMR.ONE client app (package name: `xuro`, app ID: `com.xuro`). It provides ASMR audio streaming with background playback, subtitle/lyric display, playlists, and caching. Licensed CC BY-NC-SA.

## Build & Development Commands

This project pins Flutter **3.27.0** via [`.fvmrc`](.fvmrc). Prefer `fvm flutter ...` to ensure the pinned SDK is used; substitute plain `flutter` only if you have it on PATH and matching the pinned version.

```bash
# Install dependencies
fvm flutter pub get

# Run code generation (freezed + json_serializable)
fvm dart run build_runner build --delete-conflicting-outputs

# Run the app (debug)
fvm flutter run

# Run all tests
fvm flutter test

# Run a single test file
fvm flutter test test/data/services/api_service_url_test.dart

# Static analysis (use this before commit). `withOpacity` has been fully
# migrated to `.withValues(alpha:)` (0 call-sites) — do not reintroduce it.
# Baseline is exactly 4 pre-existing, UI-unrelated warnings (unused
# import/element in playback_controller / playback_context /
# recommendation_cache_manager / playlists_content) — don't add new ones.
fvm flutter analyze

# Repo-wide `dart format lib/` will reformat files far outside whatever you are
# working on. If you run it, commit the pure-format churn separately — a
# migration diff mixed with a global reformat is unreviewable.

# Analyze a single subtree (faster feedback while iterating)
fvm flutter analyze lib/widgets/sidebar/

# Build release APK
fvm flutter build apk --release

# Build iOS (no codesign)
fvm flutter build ios --no-codesign
```

**Environment:** Dart SDK >=3.2.3 <4.0.0, Flutter 3.27.0 (FVM-pinned), Android min SDK 21 / target 33, Java 17.

**Bundled fonts:** `assets/fonts/Archivo-{400,600,800}.ttf` (OFL), declared in `pubspec.yaml` and set as `ThemeData.fontFamily`. **Archivo has no CJK glyphs** — Chinese/Japanese text falls back to the system font, so Archivo effectively styles the wordmark, numerals, durations and RJ codes only. This is a property of the design, not a defect: the design mockup's Chinese was already rendering in a fallback.

**Renderer (Android):** Impeller is **disabled** via `io.flutter.embedding.android.EnableImpeller=false` in `android/app/src/main/AndroidManifest.xml` — Android builds use the Skia backend. Reason: real-device `Vulkan: ErrorDeviceLost` → `SIGSEGV in libvulkan.so::CmdEndRenderPass+4` long-session crashes on Xiaomi HyperOS 3 / Android 16 + Adreno (driver-level GPU fault, zero Dart frames). Don't re-enable Impeller without first upgrading the Flutter SDK (3.29+ has many Adreno fixes) and re-running a 30+ min real-device session — see `docs/todos/active/20260515-upgrade-flutter-sdk.md`. iOS continues to use Impeller (default and stable there).

## Architecture

Clean Architecture with three layers, using **Provider (ChangeNotifier)** for state management and **GetIt** for dependency injection.

### Layer Structure

- **`lib/core/`** - Platform services and infrastructure
  - `di/service_locator.dart` - GetIt DI container setup (entry point for all service registration)
  - `audio/` - Audio playback system: `IAudioPlayerService` interface + implementation, PlaybackEventHub (event bus pattern), state persistence, notification handling. **Lock-screen media notification invariants** (`notification/audio_notification_service.dart` + `audio_player_handler.dart`): the Android MediaStyle notification only renders a duration-backed seekbar when the `MediaItem` carries a non-null `duration`, but at `trackChange` time the source is usually not loaded yet — so `AudioNotificationService` listens to `playbackState` and re-pushes the `MediaItem` once the real duration is known. It also injects `ISubtitleService` and, since MediaStyle has no dedicated lyric line, **puts the current subtitle line in the `artist` row** (falls back to the real artist when no line is active); `MediaItem` is only re-pushed when track/duration/lyric actually changes (lyric is `distinct`-guarded) so artwork isn't refetched. The state stream only fires on play/pause/buffer transitions, so `AudioPlayerHandler` additionally re-emits `playbackState.copyWith(updatePosition:…)` from a **1s-throttled** `playbackProgress` subscription — `copyWith` auto-stamps `updateTime = now`, letting the lock-screen seekbar extrapolate between emissions. There is no native lock-screen *scrolling* lyric (vendor-only API, deliberately out of scope). **Playback-state persistence invariants** (`state/playback_state_manager.dart` + `storage/playback_state_repository.dart`, key `last_playback_state` in SharedPreferences): the persisted `PlaybackState` is **deliberately slim** — only `work / files / currentFile / playMode / position / timestamp`. `playlist` / `currentIndex` are **not persisted**: on restore, `restorePlaybackState()` rebuilds the context via the `PlaybackContext({work, files, currentFile, playMode})` factory which re-derives playlist/index from `files`+`currentFile` (`playback_context.dart:51-68`), so persisting them was dead, duplicated tree data. Old JSON carrying those keys still loads (json_serializable ignores unknown keys — no migration). Saves are **throttled to 20s** (debounce reset on every `playerStateStream` event); explicit flushes happen on `pause()`, playback completion, and best-effort in `dispose()`. `stop()` clears the persisted key so a stopped session isn't restored. **All persistence is serialized through a single `_persistChain` future + a `_persistSuppressed` tombstone**: `clearSavedState()` sets the flag synchronously and appends the `remove` to the chain tail, so a stop's `remove` can never be overtaken by an in-flight fire-and-forget `saveState()` (which would otherwise write a stopped session back); `saveState()` snapshots `context`/`positionMs` at call time and re-checks suppression inside the chain; `updateContext(non-null)` lifts suppression for new playback. Don't reintroduce direct `_stateRepository` writes that bypass the chain
  - `subtitle/` - Subtitle/lyric system: `ISubtitleService` interface, parsers (VTT etc.), subtitle loader with caching. **`SubtitleImportService` file/DB atomicity invariants** (`subtitle_import_service.dart`, paired with `UserSubtitleRepository` SQLite + files under app-docs `user_subtitles/<workId>/`): import must never leave the user's existing subtitle in a worse state on failure. The write sequence is: `picked.copy(tmpPath)` → if a file already sits at `destPath`, move it aside to `bakPath` (`backedUp=true`) → `tmp.rename(destPath)` (atomic on same FS) → `repository.upsert`. On success: delete the backup, then best-effort delete a *different-path* old file (ext change). On any failure: delete tmp, and if `backedUp` restore `bak→destPath`, then rethrow → `ImportResult.ioError`. Never delete the old file/DB row before the new import is fully confirmed (the old "delete-old → copy → upsert" order could destroy the user's subtitle, and `File.copy` is non-atomic). `removeImportedSubtitle` removes the **DB row first** behind a `dbRemoved` flag and only deletes the local file if the DB removal succeeded — a stale row pointing at a missing file makes the app think a subtitle still exists, whereas an orphan file is harmless. These ordering rules (consistency-critical DB op gated correctly relative to the file op; existing data preserved until success) must hold for any future change here
  - `platform/` - Platform-specific: `ILyricOverlayController` (Android floating lyric window, dummy on other platforms), `WakeLockController`, `SleepTimerController`, `BackgroundPlayController`. **Sleep-timer / background-play invariants**: `SleepTimerController` is a **session-only** `ChangeNotifier` (NOT persisted — re-arming on launch is bad UX and would tangle the `playback_state` invariants); on expiry it calls `IAudioPlayerService.pause()` (deliberately `pause()`, never `stop()` — `stop()` clears the persisted key); `setMinutes`/`cancel`/`dispose` always cancel the prior `Timer` first (no double-timer / no post-dispose callback). `BackgroundPlayController` is a `WidgetsBindingObserver` with an idempotent `initialize()` (mirrors `CacheLifecycleManager`, registered lazy + `initialize()`d in `main()` after `CacheLifecycleManager`) that pauses on `AppLifecycleState.paused` **only when** `AppSettingsService.backgroundPlayEnabled == false`; default `true` preserves the always-on background behavior, it never auto-resumes and never touches `audio_service`/handler internals. Both are consumed in Settings → 播放; `SleepTimerController` also drives the player AppBar quick-timer action (opens the shared `SleepTimerDialog`, icon tinted `primary` while active). **Floating lyric invariants** (Android `LyricOverlayService.kt` + `lyric_overlay.xml`): the overlay is **pass-through by default** — `FLAG_NOT_TOUCHABLE` **and** `LayoutParams.alpha = 0.8` (`PASS_THROUGH_ALPHA`). The alpha is load-bearing, not cosmetic: Android 12+ `getMaximumObscuringOpacityForTouch()` (default 0.8) means an opaque `TYPE_APPLICATION_OVERLAY` still eats the underlying app's touches even with `FLAG_NOT_TOUCHABLE` — don't raise it above 0.8 in pass-through mode. "Edit mode" (`setEditable(true)`, entered via **long-press** the lyrics icon in `PlayerScreen`) drops `FLAG_NOT_TOUCHABLE` and restores `alpha = 1.0` so the user can drag; drag is **Y-axis only** (X is fixed `CENTER_HORIZONTAL`, only `KEY_Y` persisted — old `KEY_X` is intentionally ignored). `hide()` force-resets edit mode on both Kotlin and `LyricOverlayManager` sides. **Two ways to enter drag mode, different persistence**: long-pressing the lyrics icon in `PlayerScreen` is a *transient* session toggle (`toggleEditable`, reset by `hide()`); the **Settings → 悬浮歌词** switch is the *persisted* default — it writes `AppSettingsService.lyricOverlayUnlocked` via `LyricOverlayManager.setUnlockedPreference` and `show()` always re-applies that persisted preference last, so it is the source of truth on each show. `LyricOverlayManager` therefore depends on `AppSettingsService` (DI order: `AppSettingsService` is registered before `setupSubtitleServices()`). The lyric is a `FrameLayout` with two stacked `TextView`s (black `Paint.Style.STROKE` behind, white fill in front) — there is **no background box**; keep both TextViews' size/padding/font identical or the stroke desyncs. `setEditable` must stay wired through interface → impl → dummy → manager → native `LyricOverlayPlugin`.
  - `theme/` - **Modernist design language** (migrated 2026-08-13 from the Claude Design project "Flutter ASMR播放器设计"; its `_ds/modernist-*/styles.css` is the source of truth for the look). Theme is two axes: `ThemeMode` × `ColorVariant` (**four** now: blue/mono/green/**still**, `still` = the design's signature red `#EC3013`). `AppColors.lightSchemeFor/darkSchemeFor` hand-roll 8 `ColorScheme`s from a paper/ink pair (`paper #F3F2F2` / `ink #201E1D`) plus a shared `neutral100..900` ramp; **dark mode is paper/ink swapped** — the design only supplied light, the dark档 is derived. Surfaces stay neutral; only `primary`/`onPrimary`/`primaryContainer` rotate. Never use `ColorScheme.fromSeed`.
    - **The unassigned-token trap** (cost a real bug): `secondary` / `secondaryContainer` / `tertiary` are deliberately left unset, so Flutter fills them with fixed baseline colors that **do not rotate with variant**. `NavigationBar`'s indicator defaults to `secondaryContainer` — the bottom nav pill was the same mint green in every variant until `app_theme` pinned it to `primaryContainer`. Before using any secondary/tertiary token, assign it in all 8 schemes first.
    - **Design tokens** (mandatory; no magic numbers in UI): `AppSpacing` (4px grid), `AppRadius` (**all four levels are 0** — Modernist expresses hierarchy with 2px/1px rules, not corners or shadows; the names survive so call sites still declare intent), `AppTextStyles` (800-weight headings + negative letter-spacing; **carries no color** so the variant invariant holds), `AppAnimations`, `AppColors.dividerThickness` (2). (`MicroInteractions` was **deleted** 2026-08-13 — a full constant class for press-scale/fav-bounce that never had a single call site. Don't resurrect numbers no screen ever validated; see `docs/ui-design-spec.md` §3.2.)
    - **`app_theme` must keep overriding component shapes**: M3's buttons default to `StadiumBorder` and **do not read `AppRadius`** — without the explicit `filledButton/elevatedButton/textButton/outlinedButton/inputDecoration/snackBar/bottomSheet` themes, zero-radius silently fails across every button in the app. Light/dark share one `_base()` builder so the two definitions can't drift.
    - **Zero-radius sweep**: `grep` for `BorderRadius.circular(` / `Radius.circular(` / `BoxShape.circle` / `CircleAvatar` / `ClipOval` / `StadiumBorder` must stay at 0 hits outside `app_radius.dart`. A circle is "maximum radius" and slips past any search keyed on radius *values* — that's how the sidebar avatar survived the first sweep.
    - **Multi-variant invariant**: reusable widgets take colors from `colorScheme.*` or these tokens, never hardcode — switching variant must change *only* accent pixels. Guard with the `test/widgets/common/atom_three_variant_test.dart` pattern, and prefer asserting **through a real call site** (mount the screen) over an isolated atom.
    - `docs/ui-design-spec.md` is **v5.0**, rewritten against this system; the v4.0 reference-image content was retired wholesale by the user and is not preserved.
  - `cache/` - RecommendationCacheManager; `CacheCoordinator` (unified clean/clear API); `CacheLifecycleManager` (a `WidgetsBindingObserver` singleton — startup cleanup is deferred to `addPostFrameCallback` so the stat-heavy scan doesn't fight first-frame render; `resumed` triggers immediate cleanup; both gated by a 6h throttle + reentrancy flag). **`AudioCacheManager.cleanCache()` LRU invariants**: it must collect `(file, stat)` once via `await file.stat()` and NEVER call `statSync()` in a sort comparator (O(N log N) blocking FS calls froze frames). Eviction is true LRU: delete expired (>30d) first, then sort survivors by `stat.modified` ascending and delete oldest-first until `totalSize <= _maxCacheSize` (1GB), decrementing `totalSize` per delete. A delete failure (file in use) only skips that file — it does NOT abort the sweep. **An expired file whose delete fails must be added back into the `live` set**, not dropped: otherwise it still occupies disk but escapes capacity accounting, and actual usage can blow far past the limit. `modified` is the LRU proxy (atime is unreliable cross-platform; `LockCachingAudioSource` writes as it downloads so modified ≈ last-cached). There is intentionally no per-track pre-download capacity guard (a full dir scan on every play start would hurt the very fluency this protects). **Per-track startup cost was removed 2026-08-13**: `_getCacheDir()` memoizes its `Future<Directory>` (it was one `getApplicationSupportDirectory()` platform-channel round-trip *per track*; same `??=`-with-no-await pattern as `DatabaseService`, cleared on failure), and the `_isCacheValid` call in `createAudioSource` was deleted outright — both branches returned the same `_createCachingSource(...)` and the verdict was only logged, so it was two file-system calls per track for nothing. Expiry deletion is `cleanCache()`'s job
  - `download/` - `DownloadService` + `DownloadRepository` (`downloads` SQLite table, `UNIQUE(work_id, file_key)`): local download of any work `Child` (audio / video / **subtitle**) for offline playback. Uses an **independent `Dio()`** (no `AuthInterceptor`, doesn't rotate with node — `mediaDownloadUrl` is an API-issued presigned absolute URL). **落盘 location invariants**: only `_baseDir()`/`_workDir()` resolve the directory — **Android** uses `getExternalStorageDirectory()` (`/storage/emulated/0/Android/data/<pkg>/files/downloads/<workId>/`): permission-free on every Android version, PC-visible via USB/MTP, uninstall-cleaned; null/throw → fallback to internal `getApplicationDocumentsDirectory()`. **Non-Android always internal** (`getExternalStorageDirectory()` throws `UnsupportedError` on iOS — the `Platform.isAndroid` guard is load-bearing, don't remove it). **No migration of pre-existing internal-dir downloads** is needed or wanted: `DownloadRepository`/`DownloadEntry`, `findCompleted`/`localPathIfDownloaded`, and offline playback (`playlist_builder.dart` builds `Uri.file()`) all key off the DB's **absolute `file_path`**, so old internal files keep getting hit & played while new ones land external — don't add a migrator or switch the DB to relative paths. **Stable identity** `fileKey = md5(hash | mediaDownloadUrl | title)` (NOT the display name — same-named files under different dirs/URLs must be distinct downloads). **Disk layout** = `downloads/<workId>/<fileKey>/<sanitized original title>`: the on-disk filename is deliberately the **API's original `Child.title`** (so PC users see the real names, not an md5), and physical uniqueness is provided by the per-`fileKey` subdir — two distinct files in one work that share a `title` (e.g. each chapter's `01.mp3`) never collide. Don't flatten this back to `downloads/<workId>/<name>` (re-introduces the same-name overwrite that destroys a good file) or rename files back to the md5. `diskFileName = sanitizeFileName(title)`; `sanitizeFileName` is **Unicode-preserving** (keeps JP/CN letters — do NOT revert to the old ASCII-only `[^a-zA-Z0-9._\- ]` scrub, it mangled every Japanese ASMR title), replaces only true FS-illegal chars `[\x00-\x1F/\\:*?"<>|]`, strips leading+trailing dots/space (leading dot = hidden file on macOS/Linux; trailing = FAT eats it), `_`-prefixes Windows reserved stems (`CON`/`NUL`/`COM1`…), falls back to `file`, and UTF-8-byte-clamps to `_maxNameBytes` (180, FAT/exFAT 255-byte limit minus headroom for `.dl_tmp`/`.dl_bak`) without splitting a multibyte char — these are unit-tested boundaries, keep them. **Atomic write** mirrors `SubtitleImportService`: download to `.dl_tmp` → move any existing dest to `.dl_bak` → `rename` → DB `upsert`; any failure deletes tmp, restores bak, and never destroys an existing good file before the new one is confirmed (tmp/dest/bak are all in the same `<fileKey>` subdir so `rename` is same-volume atomic). **The entire `download()` body — including the pre-flight `findCompleted` dedup, `_destPath` resolution and tmp/bak construction — runs inside one `try`; `destPath`/`tmpFile`/`bakFile` are nullable-declared before it and the catch null-guards cleanup, so a DB open/migration, `path_provider`/dir-create or `File.exists` permission failure returns `DownloadStatus.ioError` (never an uncaught async throw). Both download dialogs (`media_download_dialog`/`batch_download_dialog`) also wrap their `await widget.download(...)` and pop a failed result on any throw, so the `PopScope canPop:false` progress sheet can't get stuck. Don't move the dedup / path resolution back outside the `try`.** `_pruneEmptyDir` best-effort removes the now-empty `<fileKey>` dir after a file delete (keeps the user-visible folder tidy; failure harmless). **Capacity** is true LRU mirroring `AudioCacheManager`: `enforceCapacity` scans the whole DB via `listAllOldestFirst()` by absolute path (NOT a dir scan), prunes rows whose file vanished, keeps & still counts (DB `size`) files that can't be `stat`/deleted, and excepts the just-finished download from eviction so a fresh download can't be reclaimed before it's returned. Don't bypass these orderings. (A `removeDownload` implementing the "DB row first, file best-effort" order existed here but had **zero callers** — no UI ever exposed "delete a download" — and was deleted 2026-08-13 along with this paragraph's description of it. If you build that feature, re-derive the ordering from `SubtitleImportService.removeImportedSubtitle`, which is live and holds the same invariant.) **`localPathsForWork(workId)`** resolves a whole work's downloads in one `listByWork` query (+ one `File.exists()` per row) and is what `PlaylistBuilder` uses — restoring an N-track work previously did N `localPathIfDownloaded` calls, i.e. N DB round-trips on the startup path. It must keep all three semantics of the per-file version: `title == null` → no entry, the **`File.exists()` gate is load-bearing** (the Android download dir is PC-visible, users delete files by hand; without the gate a missing file yields a `PlayerException` at play time instead of falling back to streaming, because `AudioSource.uri(Uri.file(missing))` doesn't throw at construction), and stale-row cleanup. `localPathIfDownloaded` stays for the single-file callers (`PlayerViewModel`, `SubtitlePreviewScreen`). **File-type classification lives in `core/files/file_kind.dart` — see that entry.** Videos route to the download-then-open-externally flow; `playFile`'s guard uses `FileKinds.isAudio` as defense-in-depth. **Batch + audio/subtitle pairing** (orchestrated in `DetailViewModel`, not the service): `collectAudioWithSubtitles(children)` is a **pure static** recursive walk that flattens the work tree to `(audio, matchedSubtitle?)` pairs — the subtitle is matched **within the same `children` sibling list** via `SubtitleMatcher` (same immediate-dir semantics as `SubtitleLoader.findSubtitleFile`/`FilePath.getSiblings`), unit-tested. `downloadFolder(folder)` (folder `null` = whole work) downloads those pairs **sequentially** (parallel would fight the LRU/atomic invariants) with aggregate `BatchDownloadOutcome`; single-file `downloadFile` also best-effort downloads the matched subtitle (subtitle network/IO failure only logs, never changes the audio's `DownloadResult`; but a subtitle download **cancel** must propagate to the batch — checked after the subtitle step AND at loop tail so a cancel during the last item's subtitle isn't misreported as "完成"). Idempotent dedup is still `DownloadService.download`'s job (don't re-add a guard in the VM). `BatchDownloadDialog.dispose()` cancels its `CancelToken` (token drives the `downloadFolder` loop's top/tail checks + dio abort) so a programmatically-dismissed dialog/page doesn't keep writing. *Note:* user-**imported** subtitles (`SubtitleImportService` → app-docs `user_subtitles/`) are a separate flow and stay internal — only *downloaded* `Child` subtitles follow the external-dir rule above. **Offline subtitle priority** (`PlayerViewModel._loadSubtitleIfAvailable`): user-imported → **downloaded-local** (the auto-matched subtitle `Child` resolved via `DownloadService.localPathIfDownloaded` + `SubtitleImportService.loadLocalSubtitle`, so a downloaded subtitle works with no network) → online `mediaDownloadUrl`; the `subtitleFile == null` early-return still clears the subtitle, and every new `await` keeps the `_loadVersion != version` race guard. **Subtitle preview** (`SubtitlePreviewScreen`, opened by tapping a `.vtt/.lrc/.srt/.txt` leaf in the file tree — `WorkFileItem` makes those tappable, routed in `detail_screen.dart`): read-only; resolves content local-first then URL via `SubtitleLoader.loadRawContent`, `parseOrNull` renders a timeline list, and **any parse failure (incl. thrown) falls back to raw text** — `parseOrNull` must keep swallowing parse exceptions so the screen never shows "加载失败" for an unparseable-but-fetched file
  - `files/` - `file_kind.dart`: **the single source of truth for "what kind of file is this `Child`"**. Added 2026-08-13 after an audit found the rule re-decided at 43 sites — 6 mutually different definitions of "is audio", 6 of "is subtitle", and 8 case-sensitive folder checks against 1 case-insensitive one. `FileKinds.of(Child)` returns a `FileKind` by a fixed precedence: **folder → video → audio → subtitle → other**. **Extension wins over the API `type`**: asmr.one mislabels some videos (e.g. "介绍视频.mp4") as `type:"audio"`; if trusted, such a file enters the audio pipeline, the playlist filters to nothing, `PlaybackContext.validate` throws "播放列表为空" and the user can neither play nor download it. So a known video extension (`{mp4,mkv,mov,avi,webm,m4v}` — deliberately excludes `m4a`) is **video** regardless of `type`. **Invariants**: (a) `FileKinds` is **pure — no DI, no `GetIt`**; the playable-format set arrives as a parameter (`isPlayable(child, {extensions})`). Making it read `AppSettingsService` would re-create the "needs DI to test" disease this module exists to cure. (b) **The two subtitle sets are deliberately different and must stay so**: `previewableSubtitleExtensions {vtt,lrc,srt,txt}` gates the read-only `SubtitlePreviewScreen` (parse failure falls back to raw text, so being lenient is harmless), while `pairableSubtitleExtensions {vtt,lrc}` gates auto-pairing for batch download and playback-time auto-load — widening *that* one makes every batch download drag an extra file per track and makes `SubtitleLoader` throw "不支持的字幕格式" where the user previously just had no subtitle. A test asserts pairable ⊂ previewable. (c) `extensionOf` uses `lastIndexOf('.')`, **not `split('.').last`** — the latter treats a dot-less name as its own extension, so a file literally named `mp3` was audio to one call site and not to its `endsWith('.mp3')` sibling. (d) `isFolder` is **case-insensitive** everywhere now; if the API ever emits `"Folder"`, the old mixed checks made batch download descend into a node the UI drew as a leaf while `FilePath.getPath` couldn't traverse it → empty playlist **and** no subtitle. Don't add a new code path that branches on `type=='audio'` alone — go through `FileKinds`.
  - `database/` - `database_service.dart` (SQLite local persistence; single `user_subtitles` table, schema version 1). **Concurrency + migration invariants**: it caches a `Future<Database>?` (`_databaseFuture`), NOT a resolved `Database` — `database => _databaseFuture ??= _open()` has no `await` between the null-check and the assignment, so under Dart's single-isolate loop concurrent first-access (the four `UserSubtitleRepository` methods each independently `await _db.database`) share one in-flight open instead of double-`openDatabase()`-ing. `_open()` clears `_databaseFuture` on failure so one failed open doesn't permanently poison the getter. Don't revert this to `Database? _database ??= await ...` (that reintroduces the double-open race). `_onUpgrade` walks an ordered `_migrations` map `{version: (db) async {...}}` for `v in (oldVersion, newVersion]` (multi-version-jump safe); to change schema: bump `_databaseVersion` AND add the step to `_migrations` (never edit `_onCreate` for an existing-install migration)
  - `image/cache/` - Image cache layer used by network image widgets

It keeps an in-memory cache (`_cached`/`_loaded`) so `AuthInterceptor` does zero storage/JSON work per request after the first load; `getAuthData()` dedupes concurrent first-loads via `_loadFuture ??= _loadAndMigrate()` (no `await` between null-check and assign). One-time migration of legacy plaintext `auth_data`: only `prefs.remove` **after** a successful secure write — migrate-fail keeps plaintext and does NOT log the user out. **Defensive degrade**: any secure-storage read/write failure (Keystore broken on some OEM ROMs) falls back to prefs rather than crashing or logging out — worst case it degrades to the old plaintext behavior. All secure/prefs *mutations* (legacy migrate, save, clear) run through a single `_serialize`/`_writeLock` chain so issue-order == persist-order — without this, an in-flight legacy-migrate `_secure.write(oldToken)` could complete after a concurrent `saveAuthData(newToken)` and resurrect the old token in secure storage. The `if (_loaded) return _cached;` guards before each cache commit protect the authoritative in-memory state when a save/clear lands during a load. Don't bypass the chain or the guards when changing this file

### Key Patterns

- **Service Locator**: All services registered in `service_locator.dart`. Access via `getIt<T>()`
- **Interface/Implementation**: Core services use interfaces (`IAudioPlayerService`, `ISubtitleService`, `ILyricOverlayController`) for testability and platform abstraction

- **Freezed models**: Data classes use `@freezed` annotation. After modifying model files, run `build_runner`
- **Platform branching**: Android gets real `LyricOverlayController`; other platforms get `DummyLyricOverlayController`

### App Initialization Flow

`main()` -> `setupServiceLocator()` -> `runApp(MyApp())` -> `MultiProvider` wraps `MaterialApp` with `AuthViewModel` + `ThemeController`.

**Cold-start invariants (2026-08-13, all subtraction — don't reintroduce the removals):**
- **ViewModels must not fetch in their constructor.** `PaginatedWorksViewModel` exposes an idempotent `ensureFirstLoad()`; each content widget triggers it from `initState`'s `addPostFrameCallback` (copy `favorites_content.dart`). Before this, `MainScreen.initState` built 4 VMs and 3 of them fired HTTP immediately — two for tabs the `PageView` never lays out.
- **No auth `await` before `runApp`.** The old comment claiming "VMs fetch with a token at construction, so auth must load first" was simply wrong: `AuthInterceptor` reads `AuthRepository.getAuthData()` per request and that repo dedupes its own in-flight load. `AuthViewModel.isAuthReady` guards the two consumers that need a resolved answer (`recommenderUuid`, `isLoggedIn`) so they hold a loading state instead of falsely reporting "not logged in".
- **Playback restore happens after the first frame and after `_initCompleter.complete()`.** It used to sit before the completer while every public method began with `await ready`, so a restore in progress blocked the user's first tap on Play.
- **Notification permission is requested at first play**, not at startup (latch-ed in `AudioNotificationService.ensureNotificationPermission()`, awaited from `resume()`; `playWithContext()` reaches it through `resume()`).
- **`main.dart`'s `getIt<BackgroundPlayController>().initialize()` must stay unconditional.** It reads like "register a lifecycle observer", but it is also the only guaranteed Dart-side audio init on the headless path (process woken from death by Bluetooth / Android Auto). That path is unverified; making it lazy risks a live service with an unwired handler.
- Startup instrumentation is a `kDebugMode`-gated `[startup] main() → first frame` print. **Debug numbers are JIT and say nothing about release** — measure with `flutter run --profile --trace-startup` and read `start_up_info.json`.

### API

Two Dio clients, both pointed at the user-selected node:
- `ApiService` — content endpoints (`/works`, `/tracks/{id}`, `/search/{keyword}`, `/review`, `/recommender/*`, `/playlist/*`, `/tags/`, `/circles/`, `/vas/`, `/workInfo/{id}`). Auth header added by `AuthInterceptor`. **`searchWorks` must build its URL via `ApiService.buildSearchUri` (`Uri.replace(pathSegments:[...])` + `_dio.getUri`), not string-concatenated `'/search/$keyword'`**: some tag names contain `/` (e.g. `巨乳/爆乳`); a concatenated `%2F` gets decoded back to `/` inside Dio's `Uri.parse`, the server splits the path → 404. `buildSearchUri` is `static` + unit-tested precisely so the keyword stays one path segment. Apply the same pattern to any future endpoint that puts user/tag text in the **path** (query params are unaffected).
- `AuthService` — `/auth/me` (login) and `/auth/reg` (register). Owns its own Dio instance, no auth interceptor.

Both services subscribe to `AppSettingsService` and rotate `dio.options.baseUrl` when the user switches nodes. Available nodes (defined in `AppSettingsService.serverOptions`):
- `https://api.asmr.one/api` (主站, default)
- `https://api.asmr-100.com/api` / `-200` / `-300` (mirror nodes)

When adding a new HTTP-touching service, follow the `_onSettingsChanged` pattern in `ApiService`/`AuthService` — don't hardcode the host. **Deliberate exception:** `UpdateService` is a third Dio client hardwired to `https://api.github.com` and intentionally does *not* follow this pattern — GitHub is unrelated to asmr node switching. Only the asmr-content/auth services rotate with the selected node.

### Error-prompt UX (connection vs. login state)

A list-page error must communicate the **right recovery action**, not just "出错了 + 重试". This invariant spans four layers — keep them consistent when adding a new paginated screen:

1. **Data**: `NetworkException.userMessage` centralizes the copy (VPN hint for connection/timeout, "请先登录" for 401/403). Don't surface `e.toString()` to users — five ViewModels used to, rendering raw Dart exception dumps on screen. Route every catch through the top-level `userMessageOf(Object)` / `isAuthErrorOf(Object)` helpers in `network_exception.dart` rather than re-implementing the type check per VM; diagnostics stay in the existing `AppLogger.error`. **Deliberate exception**: `AuthViewModel.login/register` keep `e.toString()` — `RegisteredButNotLoggedInException` overrides `toString()` with purpose-built copy, and mapping a login 401 to "请先登录" would be semantically inverted inside the login dialog itself.
2. **ViewModel**: list ViewModels (`FavoritesViewModel`, `RecommendViewModel`) expose `bool isLoginError` alongside `String? error`. Set it `true` in the not-logged-in early return **and** when a caught `NetworkException.isAuthError` is true; reset to `false` before each load and on non-auth errors. The `catch` block routes through `NetworkException.userMessage`.
3. **Widget**: `EnhancedWorkGridView` — **the only grid stack now**; the legacy `WorkGridView` and its dead `GridConfig` were deleted after a parameter-by-parameter comparison showed the enhanced one is a strict superset (its sole extra param, `bottomWidget`, was always a `PaginationControls` and is expressible as the `currentPage/totalPages/onPageChanged` triple). It takes `isLoginError` + `onLogin` (optional, defaulting to retry); when `isLoginError && onLogin != null` it renders **"去登录" instead of "重试"**. `GridError` owns the branching. Two behaviors that only existed correctly here and are now global: loading replaces content **only when `works.isEmpty`** (paging no longer swaps the list for a bare spinner and loses scroll position), and `error` is shown **only when `works.isEmpty`** — VMs don't clear `_works` on failure, so stale content must win over an error page.
4. **Screen**: content screens pass `isLoginError: vm.isLoginError` and an `onLogin` that opens `LoginDialog` on the **root navigator** (`useRootNavigator: true`), `await`s it, and reloads the list if `context.read<AuthViewModel>().isLoggedIn` afterward. The standalone `FavoritesScreen` (sidebar route, still on legacy `WorkGridView`) is wired the same way for parity. `RecommendContent`'s `Selector` record must include `isLoginError` so the grid rebuilds when it flips.

## CI/CD

GitHub Actions (`.github/workflows/build.yml`) triggers on `v*` tags. Builds Android APK/AAB (signed) + iOS IPA, creates GitHub release with changelog. A tag containing `-` (e.g. `v1.3.0-rc.1`) is auto-marked `prerelease`; **the `Notify Telegram` step keys off that same condition** to post the release to the `@XuroAsmr` channel — keep the two in sync or a prerelease will announce itself. It needs a `TELEGRAM_BOT_TOKEN` repo secret, is `continue-on-error` (a failed notification must not redden a good build), and passes every `${{ }}` value through `env:` rather than interpolating into the `run:` shell — commit messages are attacker-writable, and direct interpolation is script injection.

Widget tests for `PlayerProgress`/`WaveformProgress` and full screens with heavy DI are intentionally omitted (no shared harness; consistent with the existing no-full-DI policy). There is no app-level widget smoke test (the old `flutter create` counter boilerplate was removed). Skeleton loading is `SkeletonPulse` only — the `shimmer` package has been **removed from `pubspec.yaml`**; don't reintroduce it. Keep new tests network-free (the URL test short-circuits Dio via an `InterceptorsWrapper` that rejects in `onRequest`).
